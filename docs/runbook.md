# 운영 런북 (Runbook)

프로젝트 기간 동안 실제로 사용한 점검·대응 명령을 상황별로 정리했다.

## 1. 배포 후 확인

```bash
# 새 JAR가 올라왔는지 (타임스탬프 확인)
ls -lt /home/ubuntu/app/

# 서비스 상태 — active 여부보다 "since ~ ago"와 restart counter를 볼 것
sudo systemctl status nextplan

# 정상 기동 로그 확인
sudo journalctl -u nextplan -n 50 --no-pager | grep "Tomcat started\|Started NextPlan"
```

## 2. API가 응답하지 않을 때 (502 / 504)

```bash
# 1) 앱 프로세스 존재 여부
ps aux | grep java

# 2) 재시작 루프 여부
sudo systemctl status nextplan

# 3) 기동 실패 원인
sudo journalctl -u nextplan -n 100 --no-pager | grep "ERROR\|Caused by"

# 4) Nginx까지 요청이 오는지
sudo tail -f /var/log/nginx/access.log
sudo tail -f /var/log/nginx/error.log
```

## 3. 응답으로 원인 레이어 판별

| 응답 | 의미 | 확인 위치 |
| --- | --- | --- |
| 200 + HTML, `server: AmazonS3` | API 요청이 S3 Origin으로 감 | CloudFront Behavior |
| 403, `Generated by cloudfront` | 엣지(WAF 등)에서 차단 | WAF → Web ACL(Global) → Sampled requests |
| 502 / 504 | Origin(EC2) 응답 없음 · 지연 | systemd 상태, Nginx error.log |
| 500 + JSON 에러코드 | 앱 내부 예외 | `journalctl -u nextplan` |

## 4. AI 서버 점검

```bash
curl -I https://<ngrok-domain>/api/analyze
# 405 + allow: POST  → 정상
# 연결 실패 / ngrok 오프라인 페이지 → Colab 노트북 재실행
```

## 5. 환경변수 변경

```bash
sudo nano /etc/systemd/system/nextplan.service
sudo systemctl daemon-reload
sudo systemctl restart nextplan
```

프론트(`VITE_*`)는 빌드 시점에 번들에 들어가므로 GitHub Secrets 변경 후 **재배포가 필요**하다.

## 6. DB 스키마 변경 시 순서

1. RDS에 DDL 적용
2. 엔티티 반영된 JAR 배포
3. `ddl-auto: validate` 통과 확인 (`journalctl`에서 기동 로그)

순서가 어긋나면 기동 실패 → 재시작 루프로 이어진다.
